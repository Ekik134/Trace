# Trace — твой личный файловый помощник для Android.

**Trace** —  приложение для персонального управления файлами, которое решает проблему неорганизованности и сложности навигации за счёт тегирования и визуализации файлового древа.


## О проекте

Студенты и творческие специалисты часто работают с множеством файлов разных форматов, которые разбросаны по хранилищам и накапливаются бессистемно. Из-за этого теряется время на поиск нужных материалов, а поддерживать порядок вручную — не хватает ни времени, ни мотивации.

**Trace** решает две ключевые проблемы: **неорганизованность файлов** и **сложность навигации**. Вместо утомительного перемещения по папкам пользователь получает гибкую систему связей между файлами и наглядное древо иерархии.

### Целевая аудитория

Первая версия продукта направлена на **студентов** — самую объёмную заинтересованную аудиторию проекта, которой нужна удобная система для хранения учебных материалов.

## Функции

- **Тегирование файлов и добавление описания** — быстрое нахождение нужных файлов, объединение их в логические группы и связывание между собой.
- **Иерархическая связка тегов** — настройка гибких связей файлов без их дублирования.
- **Наглядное файловое древо** — отображение полной файловой системы с иконками, позволяющее быстрее находить нужную группу файлов.
- **Поиск и фильтрация** — поиск по названию и тегам прямо с главного экрана.
- **Добавление файлов** — в приложении можно хранить изображения разных форматов, видео, документы.
- **Редактирование файлов и тегов** — изменение названия, описания и тегов для любого файла.
- **Полный офлайн-режим** — все данные хранятся локально на устройстве, без необходимости подключения к серверу.


## Стек приложения

| Слой | Технологии |
|------|------------|
| **Среда разработки** | Android Studio |
| **Язык** | Kotlin |
| **Архитектура** | MVVM + Repository (локальная архитектура) |
| **База данных** | Room (SQLite) |
| **Настройки пользователя** | DataStore (Preferences) |
| **Кеширование изображений** | Coil |

### Архитектурные решения

- **Локальная архитектура** — все вычисления, обработка данных и хранение происходят на устройстве. Обеспечивает максимальную скорость отклика, конфиденциальность и работу в офлайн-режиме.
- **MVVM + Repository** — ViewModel не обращается к БД напрямую, а запрашивает данные через единый слой-репозиторий, который инкапсулирует работу с Room и файловой системой. Это изолирует UI от SQL-запросов и делает бизнес-логику тестируемой.
- **Кеширование файлов** — при импорте файл копируется во внутреннюю директорию приложения, что защищает его от удаления/перемещения в стандартном проводнике.


## Основные экраны

| Экран | Назначение |
|-------|------------|
| **StartScreen** | Проверка статуса онбординга и маршрутизация |
| **Onboarding** | Знакомство с приложением, ввод имени пользователя |
| **Home** | Недавно добавленные файлы, быстрый доступ к древу, поиск |
| **FileTree** | Иерархическая визуализация связей тегов |
| **FileList** | Сетка карточек файлов, фильтр по тегам, поиск, добавление файла |
| **FileEditor** | Редактирование файла (название, описание, теги) |
| **TagList** | Список тегов с вложенной структурой, добавление тега |
| **TagEditor** |  Редактирование тега (связи и название) |
| **Profile** | Имя пользователя и статистика по файлам |
